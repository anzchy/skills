# 连续采集协议

仅在实际播放并抓取烧录字幕时读取。目标是证明视频时间轴被连续观察，而不是只证明抓到了若干截图。

## 正式采集前：5 秒 pre-flight

正式连续转录前必须先做这一步，目标是实测当前视频与当前 Xvast 布局下合适的采样密度，并确认整页 PPT 可见。

1. 确认 Xvast 当前选中的是目标视频、总时长与倍速；将播放器定位到 00:00。pre-flight 覆盖前 5 个视频秒，而不是等待 5 秒墙钟时间。
2. 选择一个候选帧间隔连续采集前 5 秒。可先从 500 ms 试起（约 10–11 帧），但记录实采 `frame_count`、`median_frame_gap_ms`、`max_frame_gap_ms` 和播放器实际起止时间；配置值不等于实测值。人工查看原始帧，确认字幕可读、切换没有被采样间隔跨过。若最短可见字幕事件不确定或最大间隔可能漏掉短事件，缩短间隔并从 00:00 重做完整 5 秒。
3. 保存一张原始全窗口布局证据图。必须同时看见播放器内容区的上、下、左、右边界、播放器控制条，以及当前 PPT 画布的上、下、左、右四边。仅看到播放器边框或 PPT 局部都不通过。对实际采集帧还要确认字幕未被控制条遮挡。需要隐藏控件时，指针只能移到浏览器顶栏的安全区域，并确认页面滚动位置未变；禁止将鼠标移入或点击播放器下方的空白页面区域，因为该区域可滚动，可能把播放器上沿滚出视口。
4. 若 PPT 只显示一部分，先把 Xvast 页面向上滚到播放器顶部，重新截图并逐边核对 PPT。页面滚动改变布局时建立新的 `layout_profile`，旧布局的 pre-flight 和批次标记 `invalid`；在新布局下重新完成 5 秒 pre-flight。滚到顶部后仍看不到完整 PPT 四边，则禁止开始正式采集。
5. pre-flight 的进度、帧数/间隔、原始帧落盘、字幕可读性与画面完整性均通过人工检查后才可标为 `valid`。有效 pre-flight 可作为最终时间轴的起始部分，并从其末尾继续且保留批次重叠；若 pre-flight 无效，或后续改变布局/间隔，则回到 00:00 重采，不能留下时间缺口。

5 秒 pre-flight 不代表全片覆盖，也不证明 5 秒内没有未采到的极短字幕。它只证明这次采样方案和布局足以开始正式采集；字幕事件仍须逐事件审核。

## 开始前

- 运行 `scripts/xvast-capture status` 核对 `com.haihaisoft.xvast` 当前视频名称、总时长、播放位置、倍速和窗口 ID。
- 保存一张原始全窗口测试图，定位播放器、字幕带、播放控件和页面滚动位置；确认截图能落盘且字幕清晰。
- 对测试图执行源画面完整性检查：必须同时看见视频内容区的上、下、左、右边界、播放器控制条，以及 PPT 画布四边。视频上沿或下沿被浏览器视口截断、页面滚动导致只显示半幅视频、或只能看到 PPT 局部时，把 Xvast 页面滚到播放器顶部后重拍并复核；滚动后按新布局重做 5 秒 pre-flight。
- 按本协议前述步骤完成 5 秒 pre-flight，记录实际帧数、帧间隔中位数/最大值和播放器时间锚。依据短测中观察到的字幕切换选择间隔与倍速；不能默认二倍速或固定 500 ms 一定安全。控件隐藏前后的样本帧都应核对字幕下沿未受遮挡。
- `chrome://playlist` 不能被假定支持 DevTools、DOM、CDP、Canvas 或可读字幕轨。工具会话里的 JavaScript 循环不是在 Xvast 页面内运行脚本。

## 每个正式批次的 3 帧开批检查

正式长批次开始时，先按拟用间隔连续采集 3 帧，立即暂停播放器并逐帧核验：

- 每帧均能看见当前 PPT 画布上、下、左、右四边；播放器视频内容区四边和布局也与已通过的 `layout_profile` 一致。
- 字幕文字、底色和描边完整可读，没有被播放器控件遮挡。需要移开指针时，只能把鼠标移到浏览器顶栏安全区域；禁止将鼠标移入或点击播放器下方空白页面区域。
- 首、中、末三帧都通过后，记录该 precheck 的 `video_start_ms` / `video_end_ms` 和 `layout_profile`，将其标为 `valid`，再从暂停位置接续长采集。precheck 和续采分别记录，作为同一逻辑批次组的连续片段；续采起点必须等于 precheck 暂停锚点，避免媒体时间缺口。
- 任一帧只显示 PPT 局部时，将 precheck 标为 `invalid`，暂停续采，把 Xvast 页面滚到播放器顶部，保存新的全窗口布局图并建立新 `layout_profile`，然后重做 3 帧检查。若新的起始锚晚于无效 precheck 起点，回退到无效区间起点之前重采，保留必要重叠。

这样先用 3 帧确认当前批次的画面布局，再继续长批次；不能等整批完成后才首次检查 PPT 四边。

### 播放器控制层的回退预热

若按播放键后控制层会短暂覆盖烧录字幕，不能直接把播放后的头几帧纳入探针或主批，也不能事后只删掉被遮挡的首帧并把整批标为有效。探针和主批分别按以下方式开始：

1. 取目标接缝之前、且已被上一有效批次覆盖的约 10 个视频秒（`xvast-capture seek --by -10`，即 1 个 AX 步长）作为预热区间。第一批可使用有效 pre-flight 的重叠区间；后续批次使用上一有效主批的尾段。不得从尚未采集的区间开始预热。
2. 跳回预热起点后开始普通播放，立即运行 `xvast-capture park-cursor` 把指针放到浏览器顶栏安全区，不点击播放器下方空白区域。保持原页面滚动位置和 `layout_profile`。
3. 让视频在不截图的情况下播放到目标接缝附近，确认控制层已经隐藏，再启动 3 帧探针或主批采集。未截图的预热播放只是隐藏控件的缓冲，不形成任何新时间轴证据。
4. 用播放器实际整数时间锚复核接缝：新有效批次的 `video_start_ms` 必须小于或等于前一有效批次或已通过探针的 `video_end_ms`；考虑时间显示取整，默认保留至少约 1 秒可见重叠。若新起点晚于前一终点，视为缺口，回退更早并重采。
5. 3 帧探针通过并暂停后，主批若再次按播放键导致控制层重现，应再次回退到已覆盖区间预热，而不是直接续拍。主批起点可以与探针尾部重叠；重点是无缺口、字幕无遮挡，并保留实际时间锚。
6. 每个主批结束后检查首帧、中间帧和末帧。首帧仍出现控制层遮挡时整批标为 `invalid`，从更早的有效区间重新预热并整批重采。

清单的人工审核说明应记录本批是否使用回退预热、预热起点、目标接缝和实际截图起点。预热区间不需要写成有效截图批次，但相关上一批必须已经是 `valid`。

## 每批必须记录

```json
{
  "video_id": "当前视频名或稳定标识",
  "batch": "batch-001",
  "playback_rate": 2.0,
  "video_start_ms": 70000,
  "video_end_ms": 130000,
  "wall_start_ms": 1000000,
  "wall_end_ms": 1030000,
  "frame_count": 60,
  "median_frame_gap_ms": 500,
  "max_frame_gap_ms": 640,
  "layout_profile": "layout-001",
  "status": "valid"
}
```

- 视频起点须在开始截图前立即读取，终点须在最后一张截图后立即读取；不要在其间插入无关等待、截图预览或长工具调用。
- 以播放器实际起止时间作为时间锚，不用“墙钟时间 × 倍速”直接推算最终字幕时间。
- 批次之间保留足够重叠，使相邻字幕能够对齐并确认没有边界缺口。

## 批次有效性

```text
expected_progress = (wall_end - wall_start) × playback_rate
actual_progress   = video_end - video_start
```

若两者差值超过 `max(3000 ms, expected_progress × 5%)`，或最大截图间隔已经可能跨过测试中观察到的最短字幕，批次标为 `invalid`，不得进入最终时间轴。回退到上一有效批次末尾之前重采。

播放器提前暂停、视频名称改变、用户操作窗口、`xvast-capture` 报告进度条丢失、窗口 ID 变化或 Xvast 退出时，当前批次默认作废。重新获取应用状态，核对视频、倍速、时间和布局后再采。

## 布局变化

每个 `layout_profile` 至少记录播放器顶部、画面底部、字幕区域和播放控制条的位置。新批次与上一批比较：

- 页面滚动、窗口缩放或全屏切换造成坐标变化时，暂停采集，重新确定字幕区域并创建新 profile。需要移开鼠标以隐藏控件时，只能把鼠标移到浏览器顶栏安全区域；禁止将鼠标移入或点击播放器下方空白页面区域，避免触发网页纵向滚动。
- 每个新 profile 必须保存 `viewport_review`：`window_dimensions`、`player_bounds`、`video_content_bounds`、`controls_visible`、`four_edges_visible`、`scroll_state` 和原始全窗口证据图。只有 `four_edges_visible: true` 且 `controls_visible: true` 才可用于正式批次。采集脚本产生 `frames.json` 且初始状态为 `pending_manual_review`；人工核对 3 帧开批检查、批次首中末帧与进度后才改为 `valid`。
- 不能因为连续截图尺寸相同就认为布局未变；必须比较播放器在窗口中的位置。页面下滚后播放器上边界移出视口属于新布局且默认无效。
- OCR 突然连续为空而画面仍在变化时，先检查原始帧布局、当前 `layout_profile` 和裁切框是否漂移，再用 3 张原图执行 PaddleOCR `mobile` 单批 smoke。只有裁切确认正确后才排查 OCR 环境或模型；`mobile` 低置信度时用 `server` 复核。OCR 引擎失败或返回空结果不能据此判定该段无字幕，详见 [paddleocr.md](paddleocr.md)。
- 旧坐标裁出的字幕图不得用于新布局。

## 正式帧抽查

- 每个正式长批次在开始时先完成 3 帧开批检查，确认 PPT 四边完整后才继续；批次结束后再检查首帧、中间帧和末帧的原始全窗口图，三者都必须保留完整视频内容区。任一开批检查或抽查帧只显示 PPT 局部，则相关批次标为 `invalid`，回到 Xvast 修正滚动位置并重采。
- 低频抽查只能证明布局稳定，不能替代逐个最终 PPT source 的完整性审核。

## 复核时间轴

把全片分成“有字幕”“确认无字幕”“无法读取”“未采集”四种区段。只有前两种覆盖整个时间轴，且所有无法读取或未采集区段已补采，才能声明 `capture_coverage: complete`。

重点回查短字幕、快速替换、双行/滚动字幕、批次边界、换页、非 PPT 演示、片头片尾，以及截图最大间隔异常处。正常无字幕不是缺口。
