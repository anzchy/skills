# PPT 三轮审核

在查找、补漏或最终审核 PPT 时读取。目标是覆盖视频中实际展示的逻辑课件页，同时排除软件界面和不完整动画状态。

## 三轮找页

1. **无过滤时间轴**：按低频间隔生成全片缩略图，不依赖颜色、边框或 OCR，先发现不同播放模式和漏检区段。
2. **版式候选扫描**：同时识别全屏 PPT 和 WPS/PowerPoint 编辑窗口里的内部幻灯片画布。不能只依赖紫色外框、标题或固定坐标。
3. **换页密集复查**：在画面差异突变、标题变化、快速翻页和返回旧页附近提高采样密度，检查短暂展示的页面和最终展开状态。

## 候选分类

每个候选记录首次出现时间、源图、裁切框、逻辑页 ID 和以下类别之一：

- `full_slide`：播放器中完整展示的 PPT 页面，可以使用。
- `editor_canvas`：编辑软件中的完整幻灯片画布；只裁画布后可以使用。
- `presenter_view`：演讲者视图、缩略图墙或备注视图，不可使用。
- `software_ui`：网页、代码、模拟器、Excel 或其他软件界面，不可使用。
- `partial_animation`：逐条展开的中间状态，不可作为最终图片。

PPT 页面自身包含静态图表、网页截图或软件截图时仍可保留；判断依据是它是否处于完整 PPT 画布内。实际软件界面即使内容与 PPT 相同，也不是 PPT 截图。

## 逻辑页与完整状态

- 用版式、正文和上下文识别逻辑页，不能只看标题。同标题不同案例或数据区间可能是不同页。
- 一页逐条出现内容时选择离开该页前的最终完整状态；返回该页补充内容时重新比较，选择全片中最完整版本。
- 不裁正文、坐标轴、页底结论或最后一条 bullet。字幕带或播放器控件遮挡内容时，先寻找字幕完整且对 PPT 核心内容遮挡更少的同页帧；没有兼顾二者的帧时，完整字幕优先，使用 `fallback_original` 并记录被遮挡的 PPT 区域。
- 保留课程画面中的水印，不做拼接修复。

## 逐页裁切边界审核

裁切框属于每个候选帧，不属于整个视频或某种布局的固定常量。窗口缩放、全屏切换、编辑画布缩放、字幕位置和播放器控件都会改变真实边界。下方裁切的首要基线是完整保留所选帧的烧录字幕。

0. 先做 source 可用性判定，而不是直接画裁切框：确认 Xvast 播放器的视频内容区在窗口内完整可见，并确认 PPT 自身的顶边、底边、左边、右边都真实出现在 source 中。若 source 只显示 PPT 的上半或下半、任一画布边缘位于截图外、或页面滚动遮掉播放器一部分，记录 `viewport_review.source_slide_complete: false`，该 source 禁止用于正式图片；回到章节时间附近重新定位并现场截图。
   - 修补文稿时，用 `scripts/prepare_retake.py --document <md> --manifest <manifest> --output <new-json>` 取得每章候选时间窗。每一章至少核对画面标题或独有正文、是否为最终展开状态，以及它确实出现在该章讲解时段。时间点命中上一页、重复封面、网页或无关 WPS 页面时，不能因为播放器完整就通过审核。
1. 只有 source 可用性通过后，才从原始全窗口图确认当页画布的上、下、左、右边界，记录为 `slide_bounds`；同时确认烧录字幕文字及其底色、描边或阴影的完整外接边界，记录为 `subtitle_bounds`。不能从已裁图倒推，也不能沿用上一页的坐标。`slide_bounds` 不得用“当前可见内容的边缘”冒充真实 PPT 画布边缘。
2. `crop_box` 必须完整包含 `subtitle_bounds`，并在字幕下缘保留 1–3 像素安全余量。浏览器顶栏、playlist、PowerPoint/WPS 外框和无关按钮应去除。播放器控件只有在不裁断字幕时才去除；与字幕重叠或位于字幕下方时允许保留并记录。
3. 单独查看“原图裁切边界上下各 24 像素”和“最终附件底部 18%”。字幕文字、底色、描边或阴影任一部分贴近或穿过下边界，都视为裁切失败；同时检查：
   - 表格最后一行或底框；
   - 图表横轴、刻度、图例或页底结论；
   - 流程图最下方节点或连线；
   - 最后一条 bullet 的换行内容；
   - 幻灯片自身的完整圆角或页底边界（当边界是页面视觉的一部分时）。
4. 若烧录字幕或播放控件遮挡真实页底，按以下顺序处理：同页最终展开且字幕完整、遮挡较少的帧 → 同页带完整字幕的 `editor_canvas` → 保留完整字幕的原图回退。回退图允许 PPT 页底不完整，但必须保留大部分核心内容；不得通过上移下边界、抹除字幕、内容感知填充或拼帧修补制造“完整页”。若完整字幕帧中连核心内容也无法辨认，才标记“未获得可用 PPT 截图”。
5. 修改裁切后要重新生成暂存附件，不能只替换联系表或只看原图。

使用 `scripts/make_crop_audit.py --manifest <manifest> --document <md> --output-dir <dir>` 生成审核图。联系表只帮助定位；所有尺寸异常、裁切框贴近正文或页底可疑的附件必须原尺寸单独打开。

## 最终资产检查

先把审核后的图片生成到暂存目录，再检查实际待交付的 `assets/`：

- 每张图片只对应一个逻辑页，文件内容不重复；所选帧含字幕时，字幕必须完整保留。
- 每张图片必须能从最终附件反查到一张通过 viewport review 的原始全窗口 source；联系表中应同时看见 source 全窗口、播放器框、真实 PPT 四边和最终裁切。只检查最终附件本身不足以证明源 PPT 完整。
- 完整页须原尺寸确认没有浏览器顶栏、playlist、演讲者视图或无关软件窗口边框，并完整保留烧录字幕。播放器控件能在不损伤字幕时去除；回退页允许保留与字幕重叠的控件，但须记录。
- 完整页须确认标题、正文、页底、坐标轴和最后一条内容完整；回退页须记录其中未保留的部分。两类图片都不能是动画中间状态。
- Markdown 图片标题与实际页面一致，页序按首次出现顺序。
- 对照最终附件联系表逐格核对图像与章标题；相同画面重复出现、同一标题对应不同正文、片头占用正文页和网页/软件界面误作 PPT 均须返回 Xvast 复查。
- 每个有图页面均写入 `crop_review.subtitle_edge: verified_full`。完整页另写 `image_review: complete`、`crop_review.bottom_edge: verified_full` 和 `crop_review.content_edges: verified_full`。
- 回退页写入 `image_review: fallback_original`、具体 `fallback_reason` 和已知缺口；不得写 `verified_full`。

候选联系表只能辅助审核，不能代替对最终附件的检查。至少生成一份最终附件联系表，并单独打开所有尺寸异常、边缘可疑和内容相似的图片。
